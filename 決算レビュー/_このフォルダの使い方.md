# 決算レビュー — このフォルダの使い方

決算確定後の申告書提出前に行う**レビューの判定ルール**を置く。
ここにあるのは一般ナレッジ（実名なし）であり、**顧問先ごとのレビュー結果は置かない**。
レビュー結果（資料・中間結果・報告書）は顧問先データ保管庫の `20_決算レビュー/顧問先/<名前>/<期末日>/` にある。

## なぜ「申告書提出前」なのか

特例は2種類に割れる。**この区別がレビューの設計そのものである。**

| 区分 | 例 | 提出後に取り返せるか |
|---|---|---|
| **申告書で選択するもの** | 少額減価償却資産の特例、各種税額控除、欠損金の繰戻還付、圧縮記帳 | **取り返せない**（当初申告要件・明細添付要件があるもの） |
| **期末までに届出が要るもの** | 消費税の各選択届出、事前確定届出給与 | 当期は手遅れ。**翌期分として起票する** |

したがってレビューは次の流れになる。

報告書は次の順で書く（目的はリスク回避。提出前ほど①②が重要になる）。

```
①申告書・固定資産台帳と帳簿の突合（誤り・不備・違和感）
    ↓
②特例（適用したものの要件／適用していないものの検討）  ←★提出前でなければ取り返せない
    ↓
③次期に向けて（届出の期限・予定申告）→ 顧問先データ保管庫の 10_期限管理/ に期限ノートを起票
    ↓
過去期との比較
```

## このフォルダのノート

| ノート | 内容 |
|---|---|
| [[決算チェックリスト_法人]] | ①の合理性チェック項目。仕訳・残高から拾う異常のカタログ |
| [[適用特例一覧_法人]] | ①の特例判定。当期申告でまだ選べるもの／翌期に回すもの |
| [[比較分析指標]] | ②の指標定義と「要説明」とする閾値 |
| `checks.json` | プログラムが機械的に当てる判定ルール（12項目）。各項目の「チェックリスト」欄がノートの対応項目 |
| `tokurei.json` | プログラムが材料を揃える特例（TK-01〜11）。各項目の「特例一覧」欄がノートの対応項目 |
| 決算チェックリスト_個人 | **未着手**（法人を先行させる方針のため） |
| 適用特例一覧_個人 | **未着手** |

> [!important] ノートと JSON は同じ commit で直す
> どちらか一方だけ直すと、人が読むルールとプログラムが当てるルールがずれる。

## 検証のしかた

> [!danger] このフォルダのノートは全て未検証である
> 条文番号・金額基準・適用期限は AI が整理した草案である。
> **1項目ずつ原典（e-Gov・国税庁）で裏を取り、`検証状態: 検証済` に更新すること。**
> 検証が済むまで、これらは「調べる出発点」であって「根拠」ではない。

検証は項目単位で進めてよい。各表の `検証` 欄にチェックを入れていく。
**使用頻度の高い項目から検証する**のが効率的である（少額減価償却資産、交際費、賃上げ促進税制）。

## やってはならないこと

- **顧問先の実名・金額をこのフォルダに書く。** ここは一般ナレッジである。
- **未検証の適用期限をそのままレポートに転記する。** 特例は毎年度の改正で延長・廃止される。
  適用期限は**レビューのたびに原典で確認する**。
